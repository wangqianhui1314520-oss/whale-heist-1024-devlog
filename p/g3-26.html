GitHub 私有源码与 Sites 公开试玩部署

源代码仓库与在线地址以根目录 README 的发布链接为准。

源码与构建

推送到 GitHub 私有仓库的 main 分支后，.github/workflows/verify-game.yml 会执行可移植的规则、输入、关卡、剧情、存档验证，重新生成 dist/，检查正式包资源引用，并将正式包保存为保留七天的私有 Actions 构建产物。也可从 GitHub Actions 手动运行该工作流。

在线发布

使用 .openai/hosting.json 中既有的 Sites 项目，静态目录为 dist/。通过 Sites 源码工作流同步已验证源码并打包，保存对应版本后部署。游戏试玩对外公开，GitHub 仓库保持私有；正式站点只发布 dist/，不发布开发脚本、策划文档或本地测试产物。GitHub 推送只触发校验和构建，后续修改需另行发布 Sites 版本才会更新线上试玩。

本地构建

需要 Node.js 22 或更新版本：

node scripts/build-game.mjs
node scripts/verify-build.mjs
node scripts/serve.mjs --root dist

打开服务打印的 Local 地址。所有运行资源使用相对地址，支持静态托管。游戏无需服务器密钥或环境变量。

scripts/verify-art.mjs 还会读取当前创作电脑上的生成原图与提示词来源，用于本地美术溯源；其完整溯源检查不属于 GitHub 托管 runner 的发布门槛。正式包构建会检查所有待发布资源均存在，部署包校验会检查模块、样式、图片等引用。

存档

进度保存在浏览器本地。由本地网址迁移到在线网址时不会自动继承存档，可使用游戏设置中的存档导出／导入功能。
