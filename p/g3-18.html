一、范围与现状盘点

1.2 现有音频能力（src/game/audio.mjs）

项目现状

背景音乐每 4 秒循环的三音正弦和弦（harbor / evacuation 两套），默认音量 0.25

1.3 缺口（本次要解决的）

  1. 没有旋律性音乐——BGM 是正弦和弦垫，无情绪、无主题动机、四秒一循环过于机械；
  2. 没有环境音——水港、机房、警戒氛围缺失；
  3. 音色单薄——所有音效是单波形扫频，无层次、无材质感，与已有高完成度美术不匹配；
  4. 无语音——策划案允许"语音改字幕"降级，语音列为可选；
  5. 资产零登记——策划案要求"登记图像、声音和第三方资源"，音频目前无来源记录。

二、音频设计定位

整体跟随美术与剧情的"诙谐海港 × 机房电子 × 喜剧夸张"基调：

维度定位
风格轻爵士/手风琴海港小调（主角感）＋ 电子脉冲（机房/警戒感）＋ 卡通夸张音效（Q 版反馈）
BGM 情绪曲线标题(诙谐轻松) → 1–3 章(轻快带悬念) → 4 章(反转紧张) → 5 章(撤离紧迫) → 结算(滑稽加冕)
SFX 原则短促、夸张、有材质（水花/金属/纸张/电子），单次 0.1–0.5 秒
响度基准BGM −20 dB 左右垫底，环境 −28 dB，SFX 峰值 −8 dB，语音 −12 dB（相对主音量）
循环要求所有 BGM/环境音必须无缝循环（AI 生成后用编辑对齐，或叠加淡入淡出拼接）

3.4 语音层（可选，P2）

策划案允许"语音改字幕"，语音不做交付硬性要求。若做：四角色各 5–8 条中文短句（指令确认、加入、撤离提示、结算吐槽），每条 1–3 秒，AI 合成人声。

五、制作管线

  1. 生成：用 AI 音频工具按资产卡逐条生成 WAV（音乐、音效、环境声；语音另用合成人声）。每条资产卡记录目标、情绪、风格参考与时长。
  2. 转码压缩：ffmpeg 统一转码 —— BGM/环境 96kbps 立体声、SFX 128kbps 单声道、语音 96kbps 单声道，全部 MP3；长文件按循环点裁剪对齐，验证无缝。
  3. 落盘：assets/audio/{music,ambience,sfx,voice}/，命名与资产 ID 一致。
  4. 登记：assets/provenance/audio-manifest.json，逐条记录工具、日期、生成 prompt、时长、用途、游戏内引用点（满足策划案"登记声音来源"要求）。
  5. 打包：scripts/build-game.mjs 纳入 assets/audio 复制到 dist/；更新 assets/runtime-catalog.json 登记音频资源。
  6. 接入：升级 src/game/audio.mjs（见下节），构建后跑回归验证。

体积预算（受"初始包 ≤8MB"目标约束）

类数量单条约小计
BGM（P0 三首＋P1 四首）70.3–0.6MB≤3.2MB
环境音30.2–0.3MB≤0.9MB
SFX165–20KB≤0.3MB
语音（可选）2010–30KB≤0.6MB
合计——≤4.5MB（首批 P0 控制在 2MB 内）

六、代码接入设计（src/game/audio.mjs 升级）

目标：不破坏现有调用方，向下兼容。

  1. 保留现有接口：unlock() / configure() / setMuted() / setScene() / setPaused() / play(name) / dispose()，main.mjs、ui-v3.mjs 零改动即可继续工作。
  2. 新增资源加载器：启动时按需 fetch + decodeAudioData 加载音频到缓存池；短音效使用 AudioBufferSourceNode 即时触发（延迟可忽略），BGM/环境使用 buffer 循环节点实现无缝循环。
  3. play(name) 升级：内部维护 name → 资产文件（若有）映射，有文件播文件；文件缺失/未加载完时自动回退现有程序化合成，保证不静默失败。
  4. 新增 API：playMusic(id)、playAmbience(id)、stopMusic(fadeMs)；场景音乐切换用 1.5 秒交叉淡变（setScene() 内部自动切 BGM）。
  5. 混音总线：master → music / ambience / sfx / voice 四个独立子总线，各自可独立调音量；设置页新增"环境音""语音"两档（保留现有三档字段兼容旧存档）。
  6. 警戒联动：暴露/警戒 ≥70 时由 main.mjs 触发 audio.playAmbience('amb_alarm')（或直接在 setScene 逻辑中按警戒值叠层）。
  7. 静音/暂停/失焦：沿用现有 gain 衰减逻辑，暂停时 BGM/环境同步静音，恢复时同步复原。

七、优先级与工作量

档内容资产数说明
P0 必须bgm_harbor、bgm_evacuation、bgm_results＋核心 7 类 SFX（dash/impact/pickup/delivery/command-confirm/alarm/results）＋amb_harbor＋代码接入≈11 条先立起"有层次、有情绪"的声音骨架；对应策划案"七类声音必须覆盖"
P1 推荐bgm_title、bgm_investigation、bgm_story、bgm_failure＋amb_ops、amb_alarm＋其余 9 类 SFX 补齐＋警戒联动≈15 条补全情绪曲线与氛围
P2 可选四角色语音短句、结算语音播报≤20 条策划允许语音改字幕，不阻塞交付

预计总工作量：资产生成约 2 批（每批 10–15 条调用）、转码登记 1 批、代码接入与平衡 1 轮、回归验证 1 轮。P0 可在一个执行轮次内完成。

八、验证与验收

  1. 资产层：逐条试听；确认循环无缝（交叉点无爆音/断音）、时长与 ID 匹配、音量基准符合（BGM −20dB / SFX −8dB）。
  2. 集成层：浏览器实测——首次点击解锁、静音开关、三档音量独立生效、暂停/失焦暂停、第 4/5 章 BGM 自动切换（交叉淡变）、警戒报警叠层。
  3. 回退层：临时移除某条资产文件，确认该事件仍出程序化合成音（不静默）。
  4. 性能与体积：记录 dist 音频总字节；弱网下首包加载时间目标 <5s；内存中 buffer 数量不随章节累积（复用循环节点）。
  5. 双端：桌面键鼠与手机触屏各跑一遍首章教学，确认音效触发正常。
  6. 来源登记：audio-manifest.json 字段完整，可追溯到生成工具与 prompt。

九、范围说明

  • 只做《鲸鱼魔盗团》；《大肥鱼指令不清》无游戏本体，不做。
  • 短剧《鲸天魔盗团》音频已完成，不重复制作、不直接复用其配音进游戏（策划案要求核对来源与授权后再复用）。
  • 语音层默认不进 P0；若做，仅使用 AI 合成、无真人声纹。

十、待确认项

  1. 执行范围：先只做 P0，还是 P0＋P1 一次做完？
  2. 音频风格：以上"诙谐海港轻爵士＋电子脉冲"基调是否认可？若有参考音乐可直接替换风格描述。
  3. 语音层：是否要（P2），还是维持"语音改字幕"？
  4. 交付载体：音频接入游戏后，同步交付一份音频资产包（含 manifest）供提交留档，是否 OK？
