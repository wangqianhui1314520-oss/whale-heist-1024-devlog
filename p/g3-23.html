《鲸鱼魔盗团》美术资产交付说明

版本：Art Build 01；日期：2026 年 10 月 24 日。以批准的横版侧视视觉稿为方向，采用深蓝海底机房、象牙白平台、黄铜金边、青色水光和暖色灯光。角色统一使用 DeepSeek、Grok、Claude、GLM。

实际交付

当前 assets/runtime-catalog.json 登记 28 张原生 PNG，96 个运行采样区；另有 1 张独立 HUD 图标带供 HTML/CSS 状态徽章使用。assets/asset-manifest.json 记录制作状态、参考与来源。文件数与可调用区域数不同：角色和部件共用图集，头像源图也直接用于运行缩放，没有重复生成或另存裁切版。

原图与坐标约定

本轮使用内置 image_gen，全部交付 PNG 为原生生成输出的完整复制，保留原始尺寸与 Alpha，未后期裁切、缩放或拼接。实际尺寸以目录中的 images 为准，例如角色动作图集为 793×1983，头像与敌方为 1254×1254，场景图集为 1536×1024，三张背景为 1672×941；这些不是旧制作清单中的目标导出尺寸。

20 张透明 PNG 均检查到真实 Alpha 通道及完全透明像素；三张背景为 RGB 不透明图。部分资源 Alpha 最大值为 252 或 254，这是输出的实际数据，不应误记为 255。各图的尺寸、模式、字节数、透明像素数及 SHA256 保存在 runtime-catalog.json。

字段含义与用途
source_rect资源在原图里的完整分配区域，包含透明留白；用于图集取样与特效共同画布
content_rect在分配区域内以 Alpha > 8 检测得到的内容包围盒；普通精灵以此裁取显示，不会改写原图
solid_rectAlpha > 160 的实色包围盒；供边缘检查和主体识别，不能直接充当玩法碰撞盒
logical_size、anchor运行时目标显示范围与归一化锚点；适配器默认保持长宽比

按每条记录取样，不统一等分。 角色原生图集宽度为奇数，左右列会有一像素差；平台图集六个部件采用不等宽区域，UI 装饰框也按实际区域登记。不要用固定格宽重新切图，否则会截断武器、平台或装饰框。

接入方式

资源适配器 提供 AssetLibrary.load、draw、drawActor 和 drawEffect。下面示例适用于位于项目根目录的游戏入口模块：

import { AssetLibrary } from './src/render/assets.mjs';

const art = await AssetLibrary.load(
  new URL('./assets/runtime-catalog.json', import.meta.url)
);
art.drawActor(ctx, 'deepseek', 'idle', 'right', 320, 520);
art.drawEffect(ctx, 'water-dash', elapsedSeconds, 360, 480);

适配器用 fetch 载入 JSON，游戏入口应通过开发服务器访问。角色默认以 content_rect 为显示区域、以底部中心锚点放置；传入的 feetY 是美术脚底位置，仍需由角色物理状态决定。

四组特效默认 8 FPS、500ms、播放一次；可以传入 loop 反复展示。特效取样要保留完整 source_rect 和共同中心，不能每帧按内容包围盒重新居中，否则水流和斧光会跳动。solid_rect 不参与特效取样。

平台的装饰支架、管线和下方石柱不能决定碰撞盒。关卡分别定义水平站立顶面、穿越规则和触发器，使角色脚底落在真正的平台边缘。水段、墙板未保证无缝平铺，正式摆关卡时检查接缝。背景可按比例 cover 适配 16:9；角色保持等比缩放。

保留每项提示词及来源 JSON，不用“最新生成图片”推测来源。来源记录中的原始工具路径和工作区路径共同用于追溯；替换图像后应同步更新坐标、尺寸、SHA256 与相关来源记录。用户参考和概念稿不计入本轮生产 PNG，也不能标记为真实游戏截图。当前记录不表示已经核验参考图的参赛或使用授权。

待游戏开发继续完成

本包提供单张行走关键姿态，尚无完整逐帧步态；声音已在 src/game/audio.mjs 中以 Web Audio 合成。比赛主角卡状态为 waiting_for_gameplay_capture，必须在游戏接入后使用真实运行截图制作。五章关卡、约 20 分钟完整流程、存档、碰撞与操作体验仍需开发和实测，本轮美术交付不等于整款游戏完成。
