《鲸鱼魔盗团》目录迁移记录

本轮采用渐进式架构整理，保留旧路径兼容，避免影响现有存档、验证脚本和比赛部署包。

已完成

  • src/game/renderer.mjs 的绘制实现迁移到 src/render/scene-renderer.mjs。
  • src/game/renderer.mjs 保留为兼容门面，继续导出 GameRenderer，旧验证脚本无需立刻改写。
  • src/main.mjs 改从 src/render/scene-renderer.mjs 引用绘制器。
  • 新增 src/ui/styles.css 作为运行时唯一 CSS 入口，通过 @import 组合基础布局、V3 界面、视觉抛光和 SVG 图标样式。
  • index.html 只加载 src/ui/styles.css，组件样式文件路径保持稳定。
  • 新增 scripts/verify-architecture.mjs，检查目录边界、兼容门面、入口引用和样式聚合入口。

暂不迁移

  • src/core、src/game 的玩法与内容模块保持原路径。它们被多个验证脚本直接引用，贸然物理移动会扩大改动面。
  • src/main.mjs 暂时继续作为组合根。后续可以拆出 src/app/，但应先固定事件回调快照和存档行为。
  • ui-v3.mjs、world.mjs、state.mjs 暂不按文件拆分；先用模块边界和验证脚本固定行为，再逐块提取。
  • dist/、output/、deliverables/ 继续作为构建派生目录，不手动编辑。

后续迁移顺序

  1. 从 src/game/renderer.mjs 的兼容门面切换所有验证脚本到 src/render/scene-renderer.mjs，稳定后再删除门面。
  2. 将 ui-v3.mjs 按 screens/、components/、formatters/ 提取，每次保留现有 UIV3Controller API。
  3. 将 world.mjs 的移动、碰撞、警戒和指令执行提取为独立系统，并以只读 world snapshot 连接渲染器。
  4. 处理 core 对 game/story.mjs、game/safe-vuln.mjs 的反向依赖，再考虑 domain/ 与 content/ 目录。
