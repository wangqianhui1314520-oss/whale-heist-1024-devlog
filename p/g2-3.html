二、问题清单

P1-1 偶发「画面完全正常但角色不响应移动」（未定因，复现 5+ 次）

  • 现象：角色站在平台上、screen=none、grounded=true、barriers=[]（纸窗已破）、activeElement=CANVAS、无遮罩、无 nearby —— 按 A/D 完全不动，持续 4.5s 以上；换个时间点重开同一段又正常。
  • 实测取证（驱动的卡死诊断）：

walkTo 卡死(拾取 harbor-data-2) activeElement=CANVAS 目标x=500 当前x=406.7 y=490.0 screen=none grounded=true barriers=[] gates=[] nearby=无

  • 已排除：焦点落在按钮上（activeElement 是 canvas）、纸窗未破（barriers 为空）、平台边缘（y=490 在平台上）。
  • 影响：玩家会认为游戏卡死；对评审演示是致命观感。
  • 建议：人工在真实浏览器复现一次并抓 core.view().phase（若为 paused 即"无遮罩的暂停态"，属状态机漏洞）；QA 驱动已加自愈钩子：检测到 phase!=='playing' 就按 Esc→继续。

P2-2 第5章信标台：三块数据全部落在守卫巡逻区间内

  • 数据点 1040 / 1120 / 1180，守卫巡逻 1030–1200 —— 取件必然进入接触区。
  • 实测：一次完整撤离生命 100→35；另一次在信标台被直接打死（触发失败界面）。第5章接触伤害 15/次（0.55s 预警后结算）。
  • 建议：把一块数据移到信标西侧安全带，或缩短巡逻区间到 1100–1200，让"等巡逻走开"成为可行解法。

P2-3 死亡→检查点回档会静默清空「已收集未交付」的资料

  • 检查点只在「换房」和「交付完成」时创建（makeCheckpoint），房间内捡到的资料不在快照里。
  • 实测：第5章取齐 3 份后被打死 → 检查点重试回房间入口 → 背包清空、三块数据重新刷出，界面没有任何"已收集资料会丢失"的提示。
  • 建议：检查点纳入背包，或在重试确认里写明"未交付的资料会丢失"。

P2-4 冲刺惯性约 117px 且难以刹车，窄平台必掉层

  • 位移构成：33px 助跑 + 185px 冲刺 + 117px 惯性滑行；西画廊（400px）、高台（400px）上从节点西侧起冲会直接冲出边缘。
  • 实测：review-data-4 连续两次「冲刺后 (654,600)」——本应停在 490 层。
  • 建议：冲刺结束给 0.1s 强摩擦，或允许反向输入立即刹车；节点尽量放在平台中段。

P2-5 教程「跳跃」判定窗过窄

  • 只有从西码头 x ≤ 323 起跳才登记通过（lesson-bridge.mjs startX <= from.x + from.w + 3）；同样越过 45px 缺口、同样落在对面平台，从更东侧起跳不算过。
  • 实测：驱动从 x=302 起跳连续 3 次未通过，改到 x≈292 一次通过。
  • 建议：只判「起跳时脚下平台 = 西码头」，不限制精确 x。

P2-6 地面周期陷阱无预警且惩罚偏重

  • 陷阱直接 20 伤害 + 触发警报，没有预警；damageProtectionMs=700，站在陷阱上 3.5 秒必死（100 血）。
  • 第2/3章机房必须横穿陷阱区往返，第4/5章地面也各有一处。
  • 建议：激活前 0.3–0.5s 地面裂纹/闪烁（与警戒器 1.3s 预警同一套语言）。

P2-7 副房间动线：入口最西、出口更西、资料最东

  • 进副房间固定刷在 x=85，返回出口 x=65，必拿资料在 x≈1000–1180；第2–5章机房都要横穿整条地面（含陷阱/守卫）。
  • 实测：第2章单章 100s+ 中约 25s 是纯跑路，且跑路本身是主要伤害来源。
  • 建议：副房间入口/出口挪到资料侧，或机房中部加一条捷径梯路。

P3-8 结算面板「暴露」缺解释

  • 第2章暴露直接顶到 20（上限），界面没说它由公开指令/公开交付/警报加权而来，玩家无法复盘。

P3-9 队友破障指令可用性依赖"队友站哪一侧"，提示不明确

  • 第3章回程隔板、第5章接应隔板：队友若还在障碍西侧，预览直接报「静态梯路尚未连通，请换一个落脚点」，玩家无从得知"要等队友先绕过去"。
  • 实测：同一指令在不同轮次时好时坏，差异只是队友位置。
  • 建议：预览给出「队友正在绕行（预计 Ns）」，或让队友自动选择可达侧。

五、QA 工具说明

驱动 output/playthrough/play.cjs（自带 8774 端口静态服务）：

用法说明

已知局限：驱动是"脚本化玩家"，不会走位躲守卫，第5章信标台的密集巡逻是主要失分点（多次死亡触发回档），这也是没能走到"战役总结"界面的直接原因。
